# ADR-004: Lineage, catalog, gateway, and RBAC for W2-C

- Status: Accepted
- Date: 2026-11-21
- Owner: Anin (W2-C)
- Supersedes: none
- Related: ARCHITECTURE §5.5, §14, §17, §19; workplan W2-C; ADR-002, ADR-003

## Context

W2-B left observable pipelines but no answer to three governance questions: which
job produced a dataset, who owns it, and who is allowed to read or change it.
W2-C has to add Marquez lineage from dbt, Prefect, and the stream processor; a
catalog backed by `ops.dataset_registry`; TLS and routing at Traefik; a
deny-by-default Tailscale ACL; and viewer/operator/admin RBAC with an audit row
for every attempt.

## Decisions

### 1. OpenLineage emitter in Python, not `dbt-ol`

The repository already depends on `httpx`. A small emitter posts RunEvents to
Marquez and writes every event to `evidence/lineage/spool/*.jsonl` first. The dbt
hook reads `dbt/target/manifest.json` and collapses each `gold.mart_*` model to
its upstream `source` nodes, so the graph shows the chain that matters
(`silver.* -> gold.mart_*`) instead of duckdb staging tables.

Why: `dbt-ol` adds a second dbt adapter surface and a heavy dependency for one
wrapper. The spool also satisfies the workplan fallback when Marquez cannot
start: the raw event still exists on disk.

### 2. `ops.dataset_registry` is the source of truth, YAML is the seed

The business metadata moves from `catalog/datasets.yml` to postgres-core.
`serving.catalog_datasets` remains the API read model, so the W1-D contract does
not change. The seed script is idempotent and preserves `columns` and
`auto_classification` filled by the loader.

### 3. Catalog portal is a separate Streamlit app

`catalog.bmip.local` runs on 8502 with the same image as the dashboard, selected
by `BMIP_APP_PACKAGE=bmip.catalog`. It adds search, detail, schema, lineage,
quality, freshness, and role-gated admin actions. C3-C expands it to five views
without touching the business dashboard.

### 4. TLS terminates at Traefik; the dashboard and catalog stay open on the tailnet

Traefik keeps a path-based router on `:8000` for local scripts, and adds
`:80`/`:443` host routers. Certificates come from a local CA generated by
`scripts/gen_certs.py` (Python `cryptography`, no mkcert dependency). Only
Prometheus, Marquez, and the MinIO console use basic auth; the dashboard and
catalog are protected by the API's RBAC instead of a second password prompt.

### 5. RBAC lives in the API; legacy key becomes viewer

`ops.api_keys` stores Argon2 hashes and a role. Keys use
`bmip_<key_id>_<secret>` so a request resolves one row. The W1-D
`BMIP_API_KEY` keeps working as `viewer`; operator and admin actions need a
seeded key. `ops.audit_log` gets one row per `/v1` attempt, including 401 and
403, with `actor`, `role`, `action`, `status`, and `request_id`.

### 6. Dev ports bind to loopback

The compose dev overlay publishes internal ports on `127.0.0.1` and only
Traefik on `80`/`443`. `BMIP_BIND_ADDRESS=0.0.0.0` overrides this for a tailnet
demo, and the port scan records which choice was used.

## Consequences

- Marquez is a governance-profile dependency. `make governance-up` starts it; a
  normal `make dev-up` does not, so the demo stack stays lighter.
- A missing Marquez does not fail a job; events spool and can be replayed.
- Adding a new dataset now means a registry row plus `make governance`, not a
  YAML edit alone.
- Removing a key means setting `revoked_at`, not editing an environment file.
